# CMS-first portfolio
Create a draft in /admin/projects, add title, industry and summary, save, upload image/video or attach a URL, choose an uploaded image as cover, set alt text, order and featured, preview then publish. Homepage galleries use published data; /work is the complete project index with search and industry filters. Video thumbnails use an explicit image, a Cloudinary still, or the project cover. Broken image/video loads have an accessible fallback. Existing media remains unchanged; no migration. Review actual media delivery, dashboard credentials and Cloudinary configuration, draft preview and publish on staging. Before/after uses the existing explicit caption markers. Build and real-device QA still required. No claim of zero defects.

## Bulk media and layout
Multi-select image/video files; uploads run sequentially and report individual failures. Successful files remain attached when another fails. Reordering is a single serializable transaction with stable tie-breaking. Project galleries display 12 initially, then load more; homepage media frames use actual dimensions where supplied, bounded from 9:16 to 16:9, with contain fit. Run npm run qa:unit for stress fixtures (40 projects, 840 entries), ratios, and ordering. Cloudinary upload, actual images and browser acceptance still need verification.

## Portfolio Control Center
/admin/portfolio (ADMIN+) saves a single validated SiteSetting with separate automatic/manual ordered lists for Hero, moving strip, selected works, phone showcase and primary-video showreel. Gallery and comparison visibility are configurable. Hidden Hero artwork leaves headline and CTAs intact. A fallback work anchor remains when both work sections are hidden. Only published projects are selectable and stale selections are skipped publicly. Preview shows real cover order before save; full public layout is viewed after save. Media drag/drop uses an atomic transaction; touch/keyboard use existing reorder buttons. No migration. Browser acceptance and actual uploads still need testing.

## Visual-first hero
Desktop split composition prioritizes a CSS perspective scene (up to five selected project covers), with a central linked display, floating layered artwork, a phone preview using a second published image when available, responsive touch/keyboard controls, and optional playback. Mobile reduces peripheral layers. Motion respects global pause/reduced motion. Real published projects retain the dashboard's selected order; clearly labeled concept visuals appear only when the project list is empty. Legacy default hero copy is shortened without editing the database; customized text remains. Browser visual acceptance is still required.

## Project-level hero
The hero fetches up to 16 media records for each of up to 12 curated published projects independently of the main gallery's 16-project cap. Up to nine distinct media entries per project, cover first, can be selected in the hero; video plays only in the explicit full-screen viewer. Empty side positions can display additional images from the active project. Phone favors a portrait image. On mobile, art precedes supporting text and CTAs. Browser script includes desktop, laptop, mobile and narrow mobile first-viewport checks and captures hero screenshots. No client assets or DB records added.

## Full viewport / no crop hero
Desktop hero minimum height is the whole viewport (fixed navigation included). All projected panels and phone are placed in separate safe zones, with no stage/hero overflow clipping; artwork uses contain and inset frames. The global motion toggle and hero autoplay toggle are removed. The gradient retains a short four-second decorative entrance and honors reduced motion; gallery navigation remains manual, video player controls remain available. Browser QA checks the desktop hero height, projected object bounds, contain fit and absent hero motion controls. Actual browser acceptance is still required.

## Hero geometry regression
A pre-merge Chromium fixture loads the actual hero CSS, with synthetic empty frames and combinations of 1–5 panels, optional phone, seven screen/stage sizes and three mouse tilt positions (294 cases). It checks projected bounds and central-panel overlap without touching production content. The public browser workflow remains a separate post-deployment check. A local isolated reproduction of the final positioning rules passed all 294 cases; the full stylesheet fixture runs in CI.
