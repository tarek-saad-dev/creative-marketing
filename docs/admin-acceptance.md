# Admin acceptance
The admin-browser job creates an ephemeral PostgreSQL 16 service, applies committed migrations, seeds only synthetic owner/admin/editor/viewer accounts and lead/media fixtures, and runs the actual application with the Neon adapter connected through a loopback WebSocket-to-TCP bridge. The bridge and transport override are allowed only when CI=true, CM_QA_LOCAL_DATABASE=1, and the URL is exactly the isolated 127.0.0.1:5432/cm_admin_qa database. Never configure this flag for deployment. No production credentials or external Cloudinary calls.
The browser checks protected routes, 22 admin routes at 1440, 390 and 320 px, mobile menu, role-specific access, project draft and media reuse, publish and homepage draft isolation, CRM follow-up/contact, stale write denial, and suspended sessions. History restore and archived private preview are mandatory; verify that restore does not publish until explicitly approved. Owner password reset must invalidate an existing admin session and allow login with new credentials. Screenshots are uploaded for review. Failing checks must be investigated rather than waived. Live Cloudinary upload, production authenticated acceptance, actual owner login and mail delivery are not established by this CI fixture.
